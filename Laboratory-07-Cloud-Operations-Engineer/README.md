# Laboratory 7 – The Cloud Operations Engineer

## Mission Overview

Congratulations! Your previous work in deploying multi-tier applications has helped you develop the skills needed to join the Cloud Operations Team, also known as Site Reliability Engineering (SRE), at CloudNova Technologies.

Deploying an application is only the beginning. Keeping it stable and running properly is another important responsibility. When a server crashes or a website becomes slow, engineers need to investigate the problem instead of simply guessing what caused it. This is where monitoring and observability become useful.

In this laboratory, I used the KillerCoda Playground to perform the tasks of a Cloud Operations Engineer. I checked the performance of my Linux server, deployed a web application using Docker, generated HTTP requests, and examined system metrics and application logs to understand how the application was performing.

## Objectives

- Use Linux command-line tools to monitor CPU, memory, and disk usage.
- Deploy a web server inside a Docker container and monitor its performance.
- Generate HTTP requests and examine application access logs.
- Understand how to interpret performance data and document the results using Markdown.
- Continue improving my GitHub Cloud Computing Portfolio.

## Monitoring Commands Executed

| Command | Purpose |
|---|---|
| `free -h` | Checks the system's RAM usage and available memory. |
| `df -h /` | Displays the total, used, and available storage of the root filesystem. |
| `top` | Monitors running processes and real-time CPU and memory activity. |
| `docker run -d -p 8080:80 --name client-website nginx` | Creates and starts an Nginx web server container in the background. |
| `docker ps` | Displays the currently running Docker containers. |
| `curl http://localhost:8080` | Sends an HTTP request to check if the website responds. |
| `curl http://localhost:8080/hidden-admin-page` | Sends a request to a nonexistent page to generate a 404 error. |
| `docker logs client-website` | Displays the logs generated by the Nginx container. |
| `docker stats` | Shows real-time CPU, memory, and network usage of running containers. |

## Skills Learned

Through this laboratory, I learned how to monitor server resources using Linux commands and deploy a web server using Docker. I also practiced sending HTTP requests to test whether the website was responding correctly and generating requests to observe how errors appear in application logs.

Additionally, I learned how to use `docker stats` to check container resource consumption and understand the importance of monitoring application performance.

Overall, this activity gave me a better understanding of the responsibilities of a Cloud Operations Engineer. It showed me that monitoring system resources, analyzing logs, and identifying possible issues are important parts of keeping applications stable and reliable.
